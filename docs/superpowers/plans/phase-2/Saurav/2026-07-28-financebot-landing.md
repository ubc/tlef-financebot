# FinanceBot Landing (Pre-Login) Screen — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Owner:** Saurav

**Goal:** Replace the generic "TLEF Starter" pre-login screen with the FinanceBot login screen from the team's Figma wireframe (`0 - Login`).

**Architecture:** Client-only change. `views/landing.ts` is rewritten from a
two-column hero + health-card grid into the wireframe's single centered login
card (wordmark / CTA / redirect note). The `.landing__*` CSS block is replaced
by a `.login-card` block plus a minimal `.landing` centering wrapper, with a
`[data-theme="dark"]` counterpart because the wireframe only specifies light.
`APP` in `config.ts` is reduced to the fields the new screen actually uses, and
the two `'FinanceBot'` string literals in `main.ts` are routed back through
`APP.name` now that the app-wide re-skin point finally says FinanceBot.

**Tech Stack:** Framework-free TypeScript ES modules compiled by `tsc`
(`client/src/*.ts` → `client/public/js/`), hand-written CSS with custom-property
tokens in `client/public/styles/main.css`, Playwright for e2e + axe-core a11y.

## Global Constraints

- **Client-only.** No server, route, or API-contract changes. Nothing under
  `server/` is touched.
- **The `.js` import rule:** imports between client source files use the
  compiled `.js` extension (`import { el } from '../dom.js'`). See
  `client/AGENTS.md`.
- **Never edit or commit `client/public/js/`** — it is generated by `tsc` and
  git-ignored.
- **Copy is verbatim from the wireframe.** Button label `Log in with CWL` +
  a `→` glyph; note text exactly `You'll be redirected to UBC's CWL login.`
  (Unicode right single quotes `’`, not ASCII apostrophes). Wordmark exactly
  `FinanceBot`.
- **Both themes must work.** The app ships light + dark via
  `:root[data-theme="dark"]` in `main.css`; the landing must be legible in both
  even though the wireframe only draws light.
- **Zero axe WCAG 2.0/2.1 A+AA violations** on the landing screen —
  `tests/a11y/a11y.spec.ts` enforces this and must keep passing.
- **The login-failed banner stays.** `?login=failed` must still render the
  `banner banner--error` alert; it is functional error handling, not decoration.
- **The login link must stay a link** (`<a href="/auth/ubcshib">`), not a
  button — it is a full-page navigation to the IdP, and three existing tests
  match it via `getByRole('link', { name: /log in with cwl/i })`.
- **`APP.version` is pre-existing dead config** (no reader anywhere in
  `client/src`). It is out of scope — leave it exactly as it is. Do not remove
  it and do not add a consumer for it.
- Use `rem` for font sizes to match the surrounding stylesheet's convention
  (`1rem` = `16px`), and the existing `--radius-sm` / spacing idioms where they
  fit. Raw hexes from the table above are acceptable as new landing-scoped
  custom properties.

- [ ] **Step 4: Rewrite the landing view**

Replace the entire contents of `client/src/views/landing.ts` with:

```ts
// The pre-login screen. Everything else in the app is behind CWL login; this
// screen is rendered into the #app root when there is no session.
//
// Mirrors Figma "Wireframe v0.2" frame `0 - Login` (file 3lSS05Sk1OWpnxFQNyVsM9,
// node 148:5448): one centered card holding the wordmark, the CWL button, and a
// redirect note — deliberately nothing else. The system-health card that used to
// live here still exists on the signed-in overview (views/home.ts).
import { APP } from '../config.js';
import { el, mount } from '../dom.js';

/** Show a banner if the IdP bounced us back with ?login=failed. */
function loginBanner(): HTMLElement | false {
  const failed = new URLSearchParams(window.location.search).get('login') === 'failed';
  return (
    failed &&
    el(
      'div',
      { class: 'banner banner--error', role: 'alert' },
      el('strong', { text: 'Login failed. ' }),
      'The IdP rejected the sign-in — usually a certificate or callback-URL ' +
        'mismatch. See the Authentication section of the README.',
    )
  );
}

export function renderLanding(root: HTMLElement): void {
  // The arrow is decorative: hiding it keeps the link's accessible name exactly
  // "Log in with CWL" instead of "Log in with CWL right arrow".
  const card = el(
    'div',
    { class: 'login-card' },
    el('h1', { class: 'login-card__wordmark', text: APP.name }),
    el(
      'a',
      { class: 'login-card__cta', href: '/auth/ubcshib' },
      'Log in with CWL',
      el('span', { class: 'login-card__arrow', 'aria-hidden': 'true', text: '→' }),
    ),
    el('p', {
      class: 'login-card__note',
      text: 'You’ll be redirected to UBC’s CWL login.',
    }),
  );

  mount(
    root,
    el(
      'div',
      { class: 'landing' },
      el('main', { class: 'landing__main' }, loginBanner(), card),
    ),
  );
}
```

Note the two `’` characters in the note text — they are Unicode right single
quotes (U+2019), matching the wireframe. The Playwright assertion in Step 1 uses
the same glyphs.
