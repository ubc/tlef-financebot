# Outline capability distinctness: experimental implementation

The retained ten-file proposal contains 142 reviewed objectives, of which 119
were source-supported. The existing evidence-overlap inventory reported zero
redundant pairs. A source audit nominated L104/L127, L105/L128 and L106/L128;
these objectives were reviewed in separate batches. Shared evidence does not
itself establish equivalent instructional operations.

This change adds an explicit, experimental
`outline-capability-distinctness-v1` selector. It nominates at most two complete
peers per objective across the whole immutable proposal, before review packing.
The existing independent review receives each nominated peer's full wording
and exact original sections and returns source support and operation comparisons
in the same call. There is no new embedding stage or standalone model stage.
The existing per-send and inherited run allowances remain authoritative.

The legacy grounding and review modules remain byte-identical. Historical
selector absence retains their exact planner, prompts, parser and protocol
hash. Unknown selectors refuse work. New strict comparison rows are persisted
and replayed at continuation and course-fenced adoption. Missing or invalid
comparisons use the existing bounded correction allowance. Uncertain,
equivalent and partially overlapping unchanged wording remains outside the
selectable hierarchy; source-supported and capability-held counts are separate.
This is a detection/admission increment, not completed semantic consolidation.

## Actual integration and budget limits

The new source/peer review driver is separate from the unchanged historical
modules. The generation worker, durable checkpoint parser, raw-attempt replay,
review continuation and ordinary course-fenced Apply use the explicit selector.
Reciprocal judgments that disagree become exact failures in the current pending
row and can use its existing second attempt; previously retained rows remain
unchanged. No correction forces a positive verdict.

The model packet emits complete candidate learning points once, complete peer
wording and original sections once, and canonical comparison references. Private
hashes/coordinates and peer-only extracted-point summaries stay in the immutable
server context. These are explicit prompt exclusions, not a claim that every
private metadata field is sent losslessly. New checkpoints store context-owned
sources and reconstruct prompts instead of duplicating both rendered text and
source arrays. Initial and subset retries reconstruct the same full bindings.

Planning measures both the raw prompt and single-user JSON envelope plus the
existing JSON-format correction suffix. It repacks under the unchanged per-send
limits. Before the first source/peer review purchase, the worker records the
minimum known full-review sends, native inputs and 6,000-token output
reservations, and refuses an insufficient inherited remainder. Logical/schema
corrections and unknown work still consume that same allowance.

The actual 142-objective proposal exposes a cost problem: complete pair-context
review substantially increases input and call reservations. The retained
remaining budget cannot fund this experimental plan. This selector therefore
remains explicit and must not become the default on the strength of unit tests
or prompt fit. The refusal is useful cost control, not a solved large-course
quality workflow. The exact packing versions, failures and final minimum are
recorded under `audit-results/outline-capability-implementation-2026-10-17/`.

## Source-ineligible peer follow-up

A later pure replay found a mechanical false hold: in six constructed cases,
the sole source-supported candidate was refused because it overlapped a peer
whose source review was already unsupported or uncertain. That peer could never
be selected. The repair makes only validated comparisons to such fully resolved
source-ineligible peers non-blocking and records them separately. Missing
verdicts/rows, invalid quotations and supported duplicate peers still block.
The original six refusals and subsequent same-input result remain separately
inspectable; these are scripted policy controls, not a real-model refusal rate.

The exception requires replay of every exact source finding through the
unchanged legacy parser, complete global source/comparison rows, and valid
original quotation witnesses. It preserves negative coverage claims only as
diagnostics. A nested `resolved-source-ineligible-peers-v1` disclosure pins the
peer source finding and comparison hashes. Missing authority emits no eligible
IDs; a third supported duplicate still blocks. Empty optional disclosures are
omitted, preserving their authority across BSON storage.

The follow-up retains all eleven exact source/evidence/wording/raw-judgment
inputs. Six constructed false holds now admit only the independently supported
LO; missing source/comparison controls, supported third duplicates and all-
supported equivalents remain withheld. Same-original distinct operations still
survive. An actual BSON-codec round-trip with production parsers/finalizers and
mocked database/session boundaries verifies successful Apply; tampering either
nested hash refuses before the simulated hierarchy write. This is mechanical
authority evidence, not actual database execution or teacher acceptance.
