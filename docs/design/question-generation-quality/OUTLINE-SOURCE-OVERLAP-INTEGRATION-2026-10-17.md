# Source-overlap packing in the experimental outline review

The explicit `outline-capability-distinctness-v1` path now groups objectives
that need overlapping original sections. The actual retained ten-file,
142-objective proposal changes from 67 review sends to 40, while retaining all
244 required directional comparisons and 594 referenced original sections.
Minimum conservative native-input plus output reservations fall from 2,674,312
to 1,908,131 units, a 28.65% measured reservation reduction. These units are not
provider tokens, billing or measured model latency.

The inherited remainder is still 995,670 units. The existing whole-review
preflight therefore still refuses before its first review purchase. This
integration does not make that retained run affordable, establish semantic
quality, generate a new outline, or enable the selector by default.

## Complete plans under unchanged limits

The shared capability renderer validates an immutable global context and emits
the same source, point, peer and comparison fields. Speculative sizing uses
only a fixed-width hexadecimal placeholder for the context hash. Every chosen
group is then rebuilt with its real bound context and measured again. The
placeholder never enters stored checkpoints, model sends or Apply authority.

The packer retains a complete recursive fallback. Its deterministic greedy
search starts with the largest singleton, considers original-section overlap,
and chooses a complete alternative only when its initial native-input plus
6,000-output reservation is strictly smaller. The search is bounded to 16,000
distinct trial groups, with a 16-item shortlist before checking other candidates
when necessary. Exhaustion retains the complete fallback; partial searches
cannot produce partial review plans.

Every group still has at most four candidates. Raw input, native input, the
exact existing first JSON correction and output limits are unchanged. Full
originals, candidate learning points, peer wording and canonical pair identities
remain mandatory. Source support, capability judgments and their correction
rules are unchanged. Review-group order can change; the final curriculum keeps
the original Topic/LO coordinates and order.

Historical absent-selector calls return directly to the unchanged legacy
planner. The explicit protocol hash also binds the new packing and cache files.
Earlier experimental checkpoints remain historical and cannot silently resume
against changed runtime code.

## Volatile planning cache

Repeated currentness and Apply checks can otherwise recompute the same grouping
inside a course transaction. A process-local cache stores only the completed
deterministic planning result. Its key binds every ordered input value and the
current complete protocol hash. Property order, own undefined, null, array
holes and shared references remain distinct; callers receive defensive clones.
Errors are not cached. Four entries and 16,000,000 encoded-payload bytes bound
retention; this is not an RSS-memory guarantee or a durable cache.

The first native-V8 serialization implementation failed clone-equivalence and
size-bound tests because array representation changed after cloning. Those
failures are retained. The final deterministic graph encoding avoids that
representation dependency while preserving distinctions the planner can observe.
Source-verdict or model-response reuse is not provided by this cache. Source
currentness, raw review history, budget and matching-course transactional Apply
continue to run normally.

One retained file-only timing pair measured the old cold planner at 6.152 seconds
and the integrated cold planner at 4.213 seconds. Two subsequent current-input
calls measured 20.1 and 19.0 milliseconds, including a fresh input clone and an
attempted mutation of a previously returned plan. Exactly one current packing
build ran. These are local pure-planning measurements, excluding setup and all
provider latency; they are not a latency benchmark or a measured cold Mongo
transaction result. A cache miss still performs planning.

## Historical source reviews need a separate contract

A separate file-only audit replayed 142 canonical findings from 30 actual
recorded source calls, preserving 119 supported findings, 23 negatives and 620
unique credits. The first 103 findings used earlier source instructions/parser;
the later 39 match current source instructions. The new same-call capability
request has different peer context and an envelope requiring comparisons.
There are zero historical comparison judgments to reuse under that contract.

The proposed independent-source/canonical-pair contract requires authenticated
raw histories, exact complete requests and model/schema/source identities,
explicit handling of historical normalization, fresh missing pair judgments,
unchanged budget accounting and transactional replay. It is not implemented by
this packing integration. Read the evidence prototype in
`audit-results/outline-source-review-reuse-2026-10-17/SOURCE-REVIEW-REUSE-PROPOSAL.md`.

## Evidence and unfinished work

The integration records exact old/current input, model-ready prompts, output
groups, source equivalence, cold/warm timings and budget refusal under
`audit-results/outline-overlap-packing-integration-2026-10-17/`. Root regression,
cache failures, current-source verification and the English reader delivery are
under `audit-results/outline-source-overlap-integration-2026-10-17/`.

An initial implementation accidentally returned an empty explicit plan instead
of preserving its previous refusal. A dedicated compatibility regression now
keeps that refusal; the absent legacy empty-input behavior stays unchanged.
The earlier passing test checkpoint predates this fix and remains historical.

The final frozen-source regression passes **20 suites / 680 tests**, complete
project typecheck and lint over the 19 relevant TypeScript files. All 34 pinned
production/test files remain unchanged across those checks. The added integration
controls recover a real checkpoint using retained scripted raw replies, finish
the other noncontiguous groups, BSON-round-trip the stored authority, and run
the actual Apply parsers/finalizers inside a matching-course transaction mock.
The original Topic/LO order survives; swapped raw items and IDs independently
refuse in recovery and Apply without advancing progress or hierarchy writes.
An actual wrapper spy also verifies BSON-restored identical inputs reuse the
plan, returned copies cannot mutate it, and changed originals cause a new build.
Focused test counts overlap this final result and must not be added to it.

Actual model acceptance, supported-overlap consolidation, visual-source semantic
coverage, professor review time and improved valid saved-question yield remain
unverified. New paid semantic testing still requires explicit approval. No model,
embedding, application database, queue or OCR work occurred in these new replays.
