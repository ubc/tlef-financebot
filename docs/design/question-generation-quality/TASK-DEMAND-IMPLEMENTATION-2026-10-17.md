# Fixed task demand in new v2 authoring

## Observed problem

The retained public P04 run requested Hard but saved an Easy Draft. Earlier code
recorded `difficultyMismatch` without making it an eligibility condition, and
its repair prompt used achieved Easy instead of the original Hard request.
Source support and a positive quality status therefore did not establish that
the teacher's requested task had been supplied. The historical observations,
actual prompts and outputs remain in `audit-results/task-demand-audit-2026-10-17/`.

## Additive contract

Fresh durable `grounded-memory-v2` requests select `task-demand-v1`; baseline,
v1, absent historical selectors, exact retries and same-UUID recovery retain
their stored contracts. Unknown or incompatible explicit selectors fail before
new work. The server persists the selector through run creation, worker dispatch
and exact retry. It is not a new client-controlled authorization mechanism.

Public explicit difficulty, question type and calculation/conceptual kind become
fixed requirements. Planning considers those dimensions, initial generation and
repair retain the requested difficulty, and a plan replacement can retire only
the exact server-marked inference row. Every other teacher clause remains binding.
Changing numbers or wording still cannot establish an independent task.

The existing source-quality call additionally returns a bounded `taskDemand`
judgment: fulfilled/unfulfilled/uncertain; supported/insufficient/uncertain source
capacity; a short rationale; a named missing operation; and at most three source
span aliases. Fulfillment needs supported exact original citations, no missing
operation and matching explicit dimensions. Labels, length and descriptor claims
alone are insufficient. The server validates schema, source scope, damaged-text
exclusions, candidate identity and the full immutable requirements hash.

An actionable unfulfilled judgment with supported capacity can guide one existing
source-bound repair or independent-task replacement. It adds no repair cycle,
generator attempt or call allowance. Insufficient/uncertain capacity remains a
scoped supply shortfall; the system does not invent prerequisites to fill a Hard
quota. No-op, persistent mismatch, bad references and exhausted budgets remain
withheld. A new candidate passes all normal numerical, answerability, source,
notation, novelty, instruction and reviewer checks afresh.

Public persistence and explicit regeneration adoption replay the bound demand
receipt against actual candidate fields, requirements and source aliases, also
inside the final course fence. New receipts bind the same empty numerical arrays
that persistence serves, avoiding an omitted-versus-empty false rejection.

## Regeneration boundary

Freeform regeneration can request a different difficulty or numerical kind.
The current question is comparison context, not a guessed desired enum target.
Fresh requests therefore pin intrinsic question type but do not inherit the old
question's difficulty/kind as fixed targets. Existing teacher changes/invariants
and the same-call demand judgment remain binding. A future explicit target field
would be needed for deterministic enum matching of a freeform difficulty change.

## Validation and cost limits

Focused scripted tests exercise hard-request repair, saved fields, forged or
stale demand receipts, adoption, no-ops, insufficient source capacity, exhausted
budgets, unknown selectors and historical compatibility. They test mechanics,
not actual model understanding or professor acceptance. All failed test runs are
retained beside the final result under
`audit-results/task-demand-implementation-2026-10-17/`.

The file-only headroom audit constructs the same six retained initial reviews
and eighteen malformed-response corrections. Initial R1 found two over-cap
corrections (24,675 and 24,222); compacting only new-selector instruction prose
reduced the largest measured correction to 23,595 under the unchanged 24,000
input ceiling. Original source, Bank, candidate and teacher data remain exact.
These are conservative admission units, not billed provider tokens. Arbitrary
future malformed responses can still exceed the cap and must stop before sending.

Six worst measured quality corrections plus four historical role prompts would
require 349,630 units across 16 sends. The unchanged 320,000 aggregate guard correctly
stops after 14 admissions with 316,426 reserved. A maximum send allowance is not a
promise to complete every path. No cap was increased and no provider work occurred.

## Unestablished outcomes

No new live model verdict, regenerated outline, saved Draft, adopted candidate,
actual Hard-task success, effective yield improvement, latency/cost reduction or
reduced professor review time is established. The six retained cases are tuning
controls selected after failures, not a held-out accuracy estimate. Historical
R5 code/declarations are preserved; a fresh file-only declaration is preparation,
not API authorization. The outstanding explicit paid-probe approval remains
required before sending any course evidence to the provider.
