## Common envelope and failure policy

The proposal allows at most 20 SDK sends, 20 physical POSTs and 600,000 conservative reservation units, serially, with SDK retries disabled. Every native JSON retry and the existing one logical schema correction consumes those same global limits. Every request retains the 24,000 input-unit ceiling and uses a common 6,000 completion-token cap, including reasoning and visible output. The common cap differs from production Luna-none quality review's 2,000 cap; production-requested and experimental caps must both be recorded.

An exhausted JSON-format cell can continue to the next scheduled cell only when both native attempts have durable, complete, known usage under that exact cell/arm/logical scope. An error name alone is insufficient. Unknown usage, uncertain transport, journal failure or a guard fault stops the entire phase and retains reservations. No restart, refill or unused R9 allowance is available. All 15 planned cells stay in the denominator, including unstarted cells.
