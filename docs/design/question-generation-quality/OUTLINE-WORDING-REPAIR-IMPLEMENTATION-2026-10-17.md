# Initial internal pilot: source-bound outline wording repair

The backend implements a deliberately restricted **one-cycle, one-or-two-target
internal pilot**. It is not a general repair workflow for all 23 withheld LOs,
an atomic-curriculum redesign, a visual-understanding solution or a new public
UI/API. No paid repair declaration or API/database execution was created by the
implementing agents. A later root-reviewed pilot must follow the public saved
question yield measurement.

## Implemented behavior

`enqueueStructureOutlineRepair()` reuses the real durable structure worker and
its atomic queued-to-running claim. `createStructureOutlineRepair()` accepts
explicit negative/uncertain IDs from a completed, fully source-reviewed parent.
It rereads the immutable source checkpoint, current completed parent and exact
progress, reconciles native cost and source/model/protocol identities, and
renders the exact complete-original repair prompt. An input exceeding 48,000
conservative shaped units is refused **before the course fence, child-run or
cycle record writes**. A known remaining budget too small for that first prompt
plus its output reservation is also refused before claiming the cycle. Nothing
is trimmed to fit.

The unique `structureRepairBranches` record binds one cycle to the exact parent
checkpoint/hash. Its immutable input contains parent run/progress hashes,
targets, source fingerprint, model/provider/protocol and the inherited budget.
Repeated compatible requests return the same child, including its terminal
failure. A different selection cannot purchase another cycle. Required course
transactions and revision CAS protect creation and progress; this new pilot
refuses uncoordinated standalone writes.

One proposal completion receives only the selected targets' complete own
originals, assigned evidence, old wording and recorded concerns. Original
instructor guidance, level and emphasis remain constraints subordinate to
source support and the wording-only scope. The model may honestly propose no
repair. Its strict response cannot supply new evidence, topics, identities,
approval, coverage or verification fields. Exact normalized duplicate names,
unknown/missing/duplicate IDs and unchanged text presented as repair are refused.
The native portable JSON correction may consume another send; there is no
automatic semantic proposal retry.

A proposed branch changes selected names and corresponding content hashes only.
The current production planner proves every untouched full binding, source
alias, evidence ID/order, position and topic unchanged. The branch stores the
new immutable proposal body/hash before independent review. Existing sibling
findings remain exact. The parent's original negative findings and attempts
remain intact; only genuinely changed bindings start their own bounded review
attempts. Unchanged/no-repair targets keep their old findings.

`reviewStructureProposal()` and the existing validator/admission path independently
review new bindings against complete current originals. The reviewer receives
the repaired wording without the proposal rationale or old rejection. A valid
negative or uncertain result stays withheld; the service does not keep rewriting
until acceptance. Positive coverage gates and current-source Apply are unchanged.
The engine has only original-source loading, native completion and coverage
finalization callbacks; it has no extraction, organization or Apply callback.

The shared worker writes a completed selectable draft only after its final
course-fenced source check. Applying it remains a separate Instructor action.
No question, student, Canvas or live hierarchy data is written by this repair
workflow.

## Cost and failure behavior

The pilot preserves the parent prefix and the unchanged parent ceilings. It
admits the smaller remaining allowance, with additional limits of **10 observable
native reservations, 48,000 shaped input units, 6,000 output units/send and
540,000 new conservative units**. For the actual completed outline prefix of
31 sends/1,454,173 units, this worst case is 41/1,994,173, below 100/2,000,000.
These are implementation bounds, not a paid-run authorization or promised cost.
Actual native transport/deadline and input/code/source pins require a later
prospective declaration.

A durable ledger exists before the proposal model call. It reserves
`max(raw prompt, single-user JSON envelope) + system bytes + 32` before SDK entry,
including every portable JSON correction. Nonstreaming is intentionally
overreserved at that hook. Failed and unknown work is never reclaimed. Native
model-call receipts remain distinct from durable reservations and hidden
provider/SDK retries remain unknown.

This first implementation permits **only a pristine worker entry**. Once a
cycle has dispatched or validated any proposal/review work, automatic re-entry
is refused, even if its last stored reply is valid. A persisted claim/unknown
native send gives a specific unknown-dispatch refusal. This avoids reporting a
fresh budget as the total of earlier work without a native-usage hydration and
reconciliation mechanism. Recovery would require a separately reviewed durable
reconciliation extension; restarting or requesting the same branch does not
reset cost, consumed corrections or semantic attempts.

Proposal/review parsed raw replies and hashes, selected changes, original
authority, unresolved dispatches, attempts and costs remain in the branch.
Source drift after a reply retains that reply/cost but prevents admission.
Cancellation/course deletion stops work; failed diagnostic writes do not mask
the original failure. The protocol hash binds both the pure proposal module and
the orchestration service, while the checkpoint binds the shared review protocol.

## Interpretation and known scope

L82's “rental value” concern is a precision/clarification issue, not proof that
outside-course content was introduced. The pilot may clarify the present value
of after-tax rental/lease cash flows without adding knowledge. L92's unmarked
convertible-preferred activity can support evaluating posed alternatives, but
cannot establish a unique financial-health signal or an answer key. Activities
are not automatically deleted. Both remain new-review hypotheses, not forced
positive judgments.

Source eligibility does not prove that every supported sub-capability survived
narrowing, that an objective is suitably atomic, or that it avoids all semantic
duplicates. A repair can cover fewer assigned points while remaining eligible;
the unchanged coverage finalizer exposes the remaining gaps. A controlled pilot
must inspect exact before/after wording and per-point coverage, not merely the
number newly supported. Splitting/rebinding is intentionally deferred because
it requires new stable child IDs/alias/position lineage rather than treating
changed siblings as already reviewed. Missing chart relationships, potential
duplicate LOs and the other withheld objectives still need separate work.

The current coverage warning also reports zero-objective sections and their
recorded visual-review/context/non-instructional passage counts separately.
It no longer calls every empty extraction non-instructional. Historical receipts
remain unchanged.

## Offline evidence

The focused suites exercise strict own-original prompts and instructor
constraints; target-only deltas; exact sibling retention; source-negative and
honest no-repair outcomes; create-time oversized input with zero writes; inherited
cost/idempotency; native JSON correction; unknown dispatch and validated replay
refusal; revision CAS; source changes after proposal/review; cancellation and
original-error preservation. They use synthetic minimal records and native
budget instrumentation with mocked transport/database boundaries, not actual
model judgments or Mongo integration.

The final integrated receipt is retained under
`audit-results/quality-lab-outline-continuation-2026-10-17/wording-repair-offline-tests-final-v2.json`.
Whole server/client typecheck and scoped ESLint are required before freezing
code for the next paid public acceptance. No repair outcome or teacher acceptance
has been measured yet.
