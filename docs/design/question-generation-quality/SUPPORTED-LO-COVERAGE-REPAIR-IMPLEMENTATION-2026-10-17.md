# Supported-objective coverage wording repair

The backend now supports the explicit internal mode
`coverage-wording-outline-repair-v1` alongside the existing withheld-wording
pilot. It can revisit one or two source-supported objectives with explicitly
selected, already assigned, globally uncredited learning points. This closes a
workflow limitation; no real model repair, added source coverage, hierarchy
Apply or improved question yield has been measured by this phase.

## Internal request and authority

`createStructureOutlineCoverageRepair(courseId, parentRunId, requestedBy,
requests, loadCorpus)` is an internal service function, not a new browser
endpoint or permission. It creates the same durable structure-repair branch/run
used by the shared structure worker. Each request is `{ id, evidenceIds }`.
There are at most two objectives and one to eight requested points per target;
duplicate objective IDs or repeated requested points within or across targets
are refused.

`resolveOutlineCoverageRepairTargets` revalidates the complete parent through
actual grounding/admission code. A target must be supported, each requested
point must belong to its immutable evidence assignment, and no supported parent
finding may already credit that point. The server derives every previously
credited target point, the original objective hash and the exact parent finding
hash. Caller-supplied preservation or eligibility fields are refused. Canonical
objective/evidence ordering follows the parent, independent of request order.

The service also rereads the completed parent, exact checkpoint and fully
reconciled progress/cost authority. Source, provider, model and protocol identity
checks remain in force. An oversized complete-original proposal or insufficient
known first-call allowance stops before the course fence, child-run or cycle
writes. No source/teacher block is shortened to fit.

## Proposal, independent review and coverage result

`createOutlineCoverageRepairPrompt` includes full unchanged own original
sections, the existing wording, explicit requested capabilities, all prior
credited capabilities and original teacher guidance/level/emphasis. It does not
send a prior positive verdict as source proof. A target can be a hypothesis
without being a taught fact. The proposal may honestly return no repair; an
unmarked activity cannot supply a definitive answer from general knowledge.

The existing strict proposal validator and body builder change selected wording
and corresponding hashes only. Topic/LO counts, identities, positions, evidence
assignments, original aliases, materials and untouched bindings remain exact.
The new immutable proposal body/hash is retained before review. No extraction,
pack synthesis, new-source expansion or automatic Apply callback is available.

The ordinary independent reviewer receives changed wording and full own
originals without the proposal rationale or an instruction to accept it.
Unchanged sibling findings are reused only with exact bindings. Each changed
target retains the existing maximum two review attempts; format correction is
not an additional semantic repair loop.

`assessOutlineCoverageRepair` verifies the parent, wording-only delta, all
present fresh bindings and exact sibling findings. Success requires changed
wording, a supported fresh target finding, every requested point and **every
previously credited target point**. Missing new credit, lost previous credit,
negative/uncertain review or no repair produces a server-computed `shortfall`.
A target review still missing after the bounded attempts is reported separately
as missing review, with no invented negative model finding. Missing/foreign/
duplicate nontarget authority or corrupted references remain malformed failures.

The durable branch stores `coverageAssessment` with version, passed/shortfall
status, per-target requested/preserved/missing/lost IDs and reasons, plus a hash
binding the exact parent, changed body, findings and targets. CAS persists this
receipt before finalization. A shortfall fails the child and skips finalization;
it neither overwrites nor optimistically falls back into the parent's result.
Even a successful child remains a draft requiring explicit reviewed Apply.

## Shared cycle, cost and compatibility

Both repair modes share the existing unique one-cycle claim for the same parent
checkpoint/hash. Selecting another mode or target set cannot purchase another
cycle. Required course transactions, revision CAS and the shared worker claim
remain mandatory; uncoordinated standalone writes are refused.

The inherited cumulative ceiling is unchanged, with at most ten new observable
native reservations, 48,000 conservative shaped input units, 6,000 output units
per send and 540,000 new conservative units, additionally bounded by the smaller
parent remainder. Proposal JSON correction and every review correction consume
these same limits. The original 31-send/1,454,173-unit prefix would leave 545,827
units under its 2,000,000 ceiling; this is context, not a paid authorization.
Failed/unknown work retains its reservations. Previously dispatched or partially
completed branches still refuse blind worker re-entry until audited native-usage
reconciliation exists.

Stored mode dispatch is explicit and unknown versions fail. The old withheld
prompt/schema behavior remains unchanged. Protocol hashes bind the exact helper
and service code; old prepared branches are not silently migrated, relabelled or
approved after a protocol mismatch. This feature adds no client-selected mode,
new model endpoint, standalone model stage, cap increase or permission grant.
